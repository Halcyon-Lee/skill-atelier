# Skill 分享信息与实际案例

日期：2026-10-24

## 产品目标与已确认决策

网站分享优秀的 AI Agent Skill，长期发展为 Skill 分享社区。用户需要在每份 Skill 中看清名称、描述、使用场景与实现效果，判断是否适合自己的任务。

用户选择了实际案例方案：实现效果通过“任务输入 → 输出结果”展示，支持文字与截图。

## 本期体验设计

### 浏览与详情

- 列表卡片保留名称和简短描述，增加简短的适用场景，帮助快速筛选。
- 详情页按名称、描述、使用场景、实现效果组织。名称和现有简短介绍位于页头；场景、案例位于完整文档之前。
- 使用场景用独立文本字段维护，支持分行列出不同情境。
- 每份 Skill 本期提供一个代表性案例，包含必填的“任务输入”和“输出结果”，支持 Markdown 的列表、代码块和引用。
- 案例可附最多 3 张截图，支持上传、预览、移除和点击查看原图。移动端纵向展示案例，图片保持比例。
- 现有完整说明文档、安装方式、来源、作者、分类和标签继续展示。

### 发布与编辑

- 新建及编辑沿用同一份表单，明确分成基本介绍、使用场景、实际案例、完整文档与安装资料。
- 名称和简短描述沿用现有字段；新增场景、任务输入、输出结果与截图管理。
- 使用场景为 5–2,000 字符；任务输入和输出结果各为 10–10,000 字符。截图可选，每张最多 5 MiB，支持 PNG、JPEG、WebP。
- 新发布的内容必须补全场景与文字案例。旧内容允许在三个新增文字字段都为空时保存原有信息；开始补充后，三个字段必须一并填写完整。
- 校验失败时在对应字段提示原因，保留已填写内容和已选截图，允许修正后重试。

## 数据与文件方案

- 在 skills 表增加 use_cases、example_input、example_output 字段，默认空字符串，使用可重复执行的增量迁移，保留现有数据库。
- 新增截图记录表，关联 Skill，记录随机文件名、内容类型、排序。文件写入项目 data 目录内的持久化子目录，不加入 Git。
- 服务端在新建、编辑、删除时检查登录身份与原有作者／管理员权限，校验截图大小及实际文件格式，使用随机文件名防止路径注入。
- 图片通过带登录校验的读取接口提供，保持现有邀请制内容访问规则。读取和删除仅使用服务端记录的文件标识。
- 保存失败清理本次新增文件；更新成功后清理已移除截图；删除 Skill 时同步清理其截图。
- 技能库和全局搜索增加使用场景匹配。
- 新库示例内容提供明确标注为“演示案例”的场景和输入／输出。现有记录缺少案例时显示“作者尚未补充案例”，不自动编造实际成果。

## 结构与验证

- 数据库迁移负责结构兼容；图片模块负责格式验证与文件生命周期；原有技能操作负责权限和保存；卡片、详情及表单负责展示和交互。
- 验证新建、编辑、重载后的持久化；文字缺失和超长提示；截图类型、体积、数量限制；图片移除和删除清理；未登录及非作者访问限制。
- 验证旧数据库、旧档案仍可读取；搜索可按场景找到内容；桌面和移动端案例与截图布局可用。
- 运行项目现有类型检查、Lint 与构建，并通过浏览器走通发布和编辑流程。

## 开发任务分级

核心确定区：四类信息独立呈现；实际案例采用任务输入与输出结果；支持可选截图；覆盖发布、编辑和详情。

待本方案确认的默认选择：一个代表性案例、最多 3 张截图、沿用当前邀请制权限、卡片增加场景摘要。这些默认选择集中实现，便于后续调整。
