# 效果展示站：设计

日期：2026-10-25
状态：用户于 2026-10-25 确认（成片自己服务器托管、全站一个二维码），第一期已实施。取代同日的《案例模型》设计（`2026-10-25-video-case-model-design.md`）。

## 产品定位

ATELIER 是一个**展示网站**，不是创作工具：

- 陈列团队用 skill + AI 能力生成的各种视频成片；
- 每条视频配上真实的抖音数据，比如播放量、点赞；
- 这些效果是**钩子**：访客看完会好奇「这是怎么做出来的」，然后加微信来咨询背后用了哪些 skill。

站内不再提供生成能力：不需要登录后创作，也没有做同款和任务。

## 已确认的决定（2026-10-25）

| 问题 | 决定 |
|---|---|
| 咨询方式 | 微信二维码 |
| Skill 展示程度 | 只给线索，不给答案：公开「用了几个 skill」「制作耗时」等概括信息，具体 skill 名称咨询时再说 |
| 访问门槛 | 完全公开；只有管理员登录后台 |
| 旧功能 | 前台下线，代码先保留：创作表单、任务、生成 worker、Skill 档案库对外不可见，只有管理员能进入，以后再决定删不删 |

## 核心单元：展示视频

一条展示视频包括：成片、它在抖音上的效果、制作线索，以及只给内部看的真实 skill 清单。

### showcase_videos

| 列 | 类型 | 公开 | 说明 |
|---|---|---|---|
| id | TEXT PK (UUID) | | |
| code | TEXT UNIQUE | ✅ | 展示编号，如 `V012`；访客加微信时报这个编号，团队就知道是哪条视频带来的咨询 |
| slug | TEXT UNIQUE | ✅ | 用于 `/v/[slug]` |
| title | TEXT | ✅ | |
| summary | TEXT | ✅ | 一两句话：这条视频为谁做、解决了什么 |
| category | TEXT | ✅ | 行业或用途，如「本地生活」「知识口播」「产品种草」 |
| tags | TEXT (JSON 数组) | ✅ | |
| film_path, poster_path | TEXT | ✅ | 成片和封面，存在 `data/showcase/<id>/` |
| aspect_ratio, duration_seconds | TEXT, REAL | ✅ | 竖屏为主 |
| douyin_url | TEXT NULL | ✅ | 抖音原视频链接，供访客自行核实 |

| production_minutes | INTEGER NULL | ✅ | 线索：「制作耗时约 20 分钟」 |
| technique_hint | TEXT | ✅ | 线索：一句模糊描述，如「AI 分镜 + 自动剪辑」，不点名具体 skill |
| skills_used | TEXT (JSON 数组) | ❌ 仅后台 | 真实使用的 skill 及说明，**任何公开接口和页面都不返回** |
| status | TEXT | | `draft` / `published` / `hidden` |
| featured, sort_order | INTEGER | | 精选和手动排序 |
| consult_clicks | INTEGER | | 「怎么做的？」按钮的点击次数，用来看哪条视频最能带来咨询 |

两条硬性规则：

- **数据必须真实**：只录入抖音后台能查到的数字。页面上同时显示截止日期和抖音原链接，后台留存截图。如果视频下架或数据无法核实，就隐藏数据，不能保留旧数字。
- **`skills_used` 不出后台**：公开查询用一个固定的字段白名单，并写测试保证公开 API 和页面 HTML 里不包含 `skills_used` 的内容。

## 页面

| 路由 | 内容 |
|---|---|
| `/` | 视频墙：竖屏卡片，封面上叠加播放量，可按行业或用途筛选，排序为精选优先，再按播放量。顶部一句话说明网站是做什么的，底部固定显示咨询入口 |
| `/v/[slug]` | 详情页：播放器、抖音数据（附截止日期和原链接）、制作线索、「怎么做的？加微信问我们」按钮，点击弹出二维码，并提示「加好友时请报编号 V012」 |
| `/admin` | 后台：上传和编辑展示视频、录入数据与截图、填写真实 skill 清单、上传二维码、查看各视频的咨询点击数 |
| `/login` | 只给管理员用，公开页面上没有入口 |

**旧路由的处理**：以下页面改为只有管理员能访问，其他人看到 404：`/styles/*`、`/favorites`、`/works/*`、`/credits`、Skill 档案库（`/library`、`/skills/*`、`/submit`、`/saved`、`/profile`）、注册页 `/join`。视频相关的写接口（`/api/video-jobs`、`/api/video-favorites`）对非管理员一律返回 404。`/api/video-previews` 继续保留，供后台查看样片。

## 文件与流量

- 成片放在 `data/showcase/<id>/film.mp4`，通过 `/api/showcase/[id]/film` 用现有的 `streamVideo(..., { public: true })` 提供，支持拖动播放。
- 封面放在同一目录，由 sharp 转成 WebP 并去掉图片元数据，沿用截图上传的处理方式。
- 数据截图存在同一目录，只有管理员能访问。
- 如果访问量上来，服务器带宽会成为瓶颈。第一期先在自己的服务器上提供，后续可以把成片迁到对象存储或 CDN，表结构不用改。
- 备份：`deploy/backup.sh` 目前只备份数据库，需要把 `data/showcase/` 也加进去。

## 合规与可信度

- 播放量是对外宣传用的数字，页面上不使用「最」「第一」「保证爆款」这类绝对化或承诺效果的说法，因为可能违反广告法。统一写成「这条视频在抖音的表现」并标明截止日期。
- 视频里如果有客户品牌或真人出镜，发布前需要拿到授权。后台录入时增加一个必选的勾选项：「已获得展示授权」。

## 分期

**第一期：上线展示站**

- 建表 `showcase_videos` 和 `site_settings`，迁移写进 `db.ts` 的迁移流程。
- 首页视频墙、详情页、二维码弹窗、咨询点击计数。
- 后台：展示视频的增删改、上传成片、封面和截图、编辑二维码。
- 按上文把旧页面改为只有管理员可见；去掉页头的「登录 / 加入」和「开始创作」。
- 验收：
  - 未登录访客能浏览全部已发布的视频，看不到任何创作或登录入口；
  - 公开 API 和页面 HTML 中不包含 `skills_used`；
  - 管理员可以从零发布一条带数据的视频；
  - 点击咨询按钮后计数会增加。

**第二期：可选**

- 数据历史：定期录入，详情页画出播放量增长曲线。
- 按「行业 × 效果」生成专题页，方便投放链接。
- 如果抖音账号开通了开放平台，可以考虑接口自动同步数据，替代手工录入。

## 待确认问题

1. **成片放在哪里播放**：本文按自己的服务器托管成片来设计。另一种做法是只嵌入抖音播放器，这样省带宽，但嵌入受抖音政策限制，而且跳转后访客会离开网站。
2. **第一批有多少条视频**：这决定首页要不要分页，以及第一期要不要做筛选。
3. **二维码数量**：全站一个，还是按行业分给不同的顾问？本文按全站一个设计。

## 修订（2026-10-25，同日第二次）：会员制案例库

上面的「完全公开」「咨询点击」「只给线索不给答案」已被取代，以下为现行方案：

- **访问**：整站登录后才能看。新用户用邀请码注册，之后用邮箱密码登录；邀请码仍由管理员在 `/admin` 签发。成片、封面、二维码接口都要求登录。
- **清单**：按用途分类（带数量），卡片显示封面、编号、时长，有抖音数据时显示播放和点赞。
- **详情页右侧**：简介 → 实现方式（标签 + 说明）→ 制作信息（成片时长、制作时长、适用场景、制作条件）→ 抖音数据（有才显示）→ 微信二维码（带编号提示）。
- **实现方式公开**：不再只给概括线索，实现方式（如代码生成、ComfyUI + 视频模型、视频模型直出）对会员公开；具体用了哪些 skill 仍只在后台（`skills_used`）。
- **二维码曝光**：原来的「咨询点击」改为详情页二维码被看到的次数（每人每条每小时计一次）。
- **文案**：面向普通访客，直白，不用「skill」等内部词，不用文艺口号。
- **新增字段**：`method_tags`、`technique_hint`（实现方式说明，≤300 字）、`scenarios`、`conditions`。
